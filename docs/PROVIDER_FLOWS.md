# 依 AI 來源分列流程圖

Windows 桌面版與 VS Code 版只有一張桌布、一個畫布：來源依首次出現順序由上往下排列；同一批首次出現時，活躍來源優先。例如 GPT/Codex 先出現，Claude 之後出現，Claude 就排在下方。快照出現其他 `Provider`／`provider` 時，也依首次出現順序向下新增節點群。所有來源共用背景、世界座標、縮放與拖曳平移，雙擊還原整張圖；點工具可展開。沒有分割面板或獨立視窗。

每個來源都有自己的 FlowModel，session、主節點、模型文字、子代理、機甲、工具種類、粒子、忙碌與淡出狀態獨立。相同名稱的工具不跨來源合併。沒有事件的來源不補造模型名稱，圖形沿用原本的閒置淡出行為。

主節點與子代理皆使用人類大腦側面圖示，依使用者參考圖呈現不規則腦迴、小腦與腦幹，配合神經節點脈衝、掃描光帶與輕微呼吸動畫，停用動態時保持靜止。主大腦較大、子代理較小並各自連到其工具。大腦旁僅顯示資料提供的模型名稱，例如 `Codex · gpt-6.1-sol` 顯示為 `GPT-6.1 SOL`；不自行補上未提供的型號。移除重複來源／模型標題及主節點、子代理節點的提示泡泡，避免遮住模型名稱；保留工具方塊與額度事件泡泡。

整張桌布永遠只繪製一組共用的裝甲手／腳：護臂表示成功輸出、裝甲腿表示失敗，成功與失敗數字彙總所有來源，摘要卡也只顯示一張。不同來源與子代理的連線、粒子、送件機甲都匯聚到相同的世界座標；各來源使用局部輸出偏移與錯開的停靠位，不能依來源複製輸出裝甲。關節動作與能量流是視覺效果，不增加虛構的工具事件或進度。

來源辨識依 session 的 provider，工具或子代理沿用其 session 的來源；工具缺少 session 時使用自身 provider。為相容既有紀錄，`codex:` session ID 視為 Codex，未指定來源的舊資料視為 Claude。Claude 的用量與額度事件只屬於 Claude，不複製到其他來源。

新增 AI 的資料接入仍需實作掃描器；掃描器只要在 session 與工具 DTO 填入一致的來源名稱，畫面會自動增加一列，不必另寫版面。Gemini 僅用於多來源測試，尚未新增 Gemini 掃描器。

實作位置：`Core/Flow/ProviderSnapshot.cs`、`vscode-extension/src/core/providerSnapshot.ts`。來源隔離測試：`Tests/ProviderFlowTests.cs`、`vscode-extension/test/providers.test.ts`。
